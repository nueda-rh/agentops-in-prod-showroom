= モジュール 3: エージェント型アプリケーションのメトリクスとログ
:imagesdir: ../assets/images
:navtitle: モジュール 3: メトリクスとログ
:toc: macro
:toclevels: 1

メトリクスは、システムで**何が**起きているかを教えてくれます。ログは、**正確に何が、いつ起きたか**を教えてくれます。このモジュールでは、mortgage-ai マルチエージェントシステムを監視する事前にデプロイされた Grafana ダッシュボードを探索し、次に OpenShift Console の LokiStack を使用してアプリケーションのログを調査します。

TIP: このモジュールでは、あなたはシステムの健全性、リクエスト率、エラー率、および運用ログに焦点を当てる **SRE / プラットフォームエンジニア** の役割を担います。

== 学習目標

このモジュールを修了すると、以下のことができるようになります：

* マルチエージェント AI システムにとって重要な主要メトリクスを特定できる
* 事前にデプロイされた Mortgage-AI Grafana ダッシュボードを操作できる
* LokiStack と LogQL (Log Query Language) を使用してアプリケーションログを探索およびフィルタリングできる
* エージェント型のオブザーバビリティにおいて、メトリクスとログがどのように連携するかを説明できる

== エージェント型のメトリクスは何が違うのか？

従来のアプリケーションでは、リクエスト率、エラー率、レイテンシが必要です。エージェント型のアプリケーションでは、それらすべてに**加えて**、LLMの動作、エージェントのルーティング、およびツールの実行をキャプチャするメトリクスが必要です。以下は、最も重要な6つのメトリクスです：

[cols="2,2,3",options="header"]
|===
|メトリクス |Prometheus での名前 |わかること

|リクエスト率とエラー
|`http_requests_total`
|どのくらいのトラフィックが来ているか？ いくつのリクエストが失敗しているか？

|レイテンシのパーセンタイル
|`http_request_duration_seconds`
|どのくらい速く応答しているか？ 外れ値はあるか？

|LLM トークン使用量
|`llm_tokens_total`
|いくつのトークンを消費しているか？ 1回の会話あたりのコストはいくらか？

|LLM 推論のレイテンシ
|`llm_inference_duration_seconds`
|モデルの応答にどれくらいの時間がかかるか？ それがボトルネックになっているか？

|ツール呼び出しの成功率
|`tool_calls_total`
|エージェントのツールは機能しているか？ どのツールが失敗しているか？

|エージェントのルーティング
|`agent_routing_total`
|クエリは高速なモデルにルーティングされているか、それとも高性能なモデルにルーティングされているか？ 分類器は機能しているか？
|===

image::agentic-app-pre4.png[Agentic Metrics - The 6 That Matter showing traditional metrics plus agentic additions with model routing and Prometheus scraping by OpenShift UWM,link=self,window=blank,width=700]

mortgage-ai の API は、これらすべてを `GET /metrics` で Prometheus 形式にて公開しています。**OpenShift User Workload Monitoring**（Red Hat OpenShift AI に付属する組み込みの Prometheus インスタンス）は、30秒ごとに自動的にそれらをスクレイピングし、時系列データベースに保存します。

つまり、Prometheus を自分でセットアップする必要はありません。プラットフォームが収集と保存を処理します。あなたが行う必要があるのは以下のことだけです：

1. アプリケーションからメトリクスを公開する（mortgage-ai はすでにこれを行っています）
2. 視覚化プラットフォーム（このワークショップでは Grafana を使用）を設定して、OpenShift の Prometheus データソース（設定済み）にクエリを実行する
3. メトリクスを視覚化するためのダッシュボードを構築する（これについては次で探索します）

[%collapsible]
.完全なメトリクスリファレンス (クリックして展開)
====
mortgage-ai のバックエンドは、`packages/api/src/core/metrics.py` で定義された 10 個のカスタムメトリクスを公開しています：

[cols="2,1,2",options="header"]
|===
|Prometheus での名前 |タイプ |ラベル

|`llm_tokens_total`
|カウンター
|`model`, `direction` (入力/出力), `persona`

|`llm_inference_duration_seconds`
|ヒストグラム
|`model`, `persona`

|`agent_routing_total`
|カウンター
|`persona`, `complexity` (単純/複雑)

|`agent_escalation_total`
|カウンター
|`persona`, `reason`

|`tool_calls_total`
|カウンター
|`tool_name`, `persona`, `status` (成功/エラー)

|`tool_call_duration_seconds`
|ヒストグラム
|`tool_name`, `persona`

|`active_chat_sessions`
|ゲージ
|`persona`

|`chat_messages_total`
|カウンター
|`persona`, `direction` (受信/送信)

|`loan_applications_total`
|カウンター
|`status`, `loan_type` (まだ計装されていません)

|`compliance_checks_total`
|カウンター
|`check_type`, `result` (まだ計装されていません)
|===

さらに、`prometheus-fastapi-instrumentator` は自動の HTTP メトリクス (`http_requests_total`, `http_request_duration_seconds_bucket`) を提供します。

=== 概要(Overview)と HTTP パネル

ダッシュボードの上部では、システムの健全性を一目で確認できます：

image::grafana2.png[Grafana Overview and HTTP panels showing request rate and latency,link=self,window=blank,width=700]

表示されている内容は以下の通りです：

* **Total Requests (Last Hour)**: API にヒットしたリクエスト数。スクリーンショットでは約 983 リクエスト。
* **Request Rate**: 現在の1秒あたりのリクエスト数（スループット）。
* **Error Rate (%)**: 5xx 応答の割合。緑色は健全であることを意味します。
* **P95 Latency**: 95% のリクエストがこの値よりも速く完了します。100ms 以下であれば素晴らしいです。

概要の下にある HTTP パネルでは、トラフィックをエンドポイントとステータスコード別に分類しています。以下に注目してください：

* 最もトラフィックが多いエンドポイントはどれか (おそらく `/api/prospect/chat`)
* HTTP Status Distribution に黄色 (4xx) または赤色 (5xx) のバーがあるか
* 最も P95 レイテンシが高いエンドポイントはどれか

[%collapsible]
.Overview パネルの PromQL (Prometheus Query Language) の詳細 (クリックして展開)
====
* **Request Rate**: `sum(rate(http_requests_total{namespace=~"$namespace"}[5m]))`
* **Error Rate**: `(sum(rate(http_requests_total{namespace=~"$namespace", status=~"5.."}[5m])) / sum(rate(http_requests_total{namespace=~"$namespace"}[5m])) * 100) or vector(0)`
* **P95 Latency**: `histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket{namespace=~"$namespace"}[5m])) by (le))`

`rate()` は、特定の時間枠における1秒あたりの平均値を計算します。`histogram_quantile()` は、ヒストグラムのバケットからパーセンタイルを計算します。
====

=== AI エージェントメトリクス

下にスクロールして **AI Agent Metrics** の行を表示します。ここからが面白くなります。これらのメトリクスは、エージェント型のアプリケーションに固有のものです：

image::grafana1.png[Grafana AI Agent Metrics showing token usage and tool call success rate,link=self,window=blank,width=700]

このセクションの上部にある 4 つの統計パネルには、以下が表示されます：

* **Active Chat Sessions**: ライブの WebSocket 接続数。現在何人のユーザーがチャットしているか？
* **Total LLM Tokens**: API が開始されてから消費されたトークンの累積数。これはコストの指標となります。スクリーンショットでは 18.5K トークンです。
* **Tool Call Success Rate**: エージェントのツールは機能しているか？ 100% はすべてが健全であることを意味します。
* **Avg LLM Latency**: LLM 推論呼び出しの中央値（レイテンシ）。スクリーンショットでは 1.75秒です。

統計の下にある詳細パネルには、以下が表示されます：

* **LLM Token Usage by Model**: 最もトークンを消費しているモデルはどれか？ 入力と出力のどちらが支配的か？
* **LLM Inference Latency by Persona**: 最も遅いエージェントのペルソナはどれか？ アンダーライターエージェントが遅い場合、複雑なコンプライアンスツールの呼び出しを示している可能性があります。
* **Agent Routing Distribution**: 単純なルーティングと複雑なルーティングの円グラフ。複雑なクエリの比率が高い場合、高性能なモデルが作業の大部分を行っていることを意味します。
* **Tool Calls by Status**: 成功は緑、失敗は赤。赤のスパイクは、ツールの統合が壊れていることを意味します。

[%collapsible]
.AI Agent Metrics の PromQL の詳細 (クリックして展開)
====
* **LLM Tokens**: `sum(increase(llm_tokens_total{namespace=~"$namespace"}[1h]))`
* **Tool Success Rate**: `(sum(tool_calls_total{namespace=~"$namespace", status="success"}) / sum(tool_calls_total{namespace=~"$namespace"}) * 100)
