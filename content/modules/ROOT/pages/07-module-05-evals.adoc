[NOTE]
====
**このモジュールはオプションです。** モジュール 1〜4 を完了していれば、オブザーバビリティの強力な基礎ができています。このモジュールは、評価フレームワークについてより深い専門知識を得たい方や、追加の時間がある方向けに、高度な品質保証機能を追加します。
====

オブザーバビリティはシステムが機能しているかどうかを教えてくれますが、評価 (Evals) はエージェントが**適切に**機能しているかどうかを教えてくれます。評価がなければ、回答の品質が 20% 低下しても、顧客から苦情が来るまで何週間も気づかれない可能性があります。このモジュールでは、基本的なオブザーバビリティを超えて、MLflow の評価フレームワーク、プロンプトレジストリ、および LLM-as-a-Judge スコアラー（ある LLM を使用して別の LLM の出力品質を評価する）を使用して、Fed Aura Capital のプロスペクトエージェントに対して LLM 評価を実行します。

TIP: このモジュールでは、あなたはモデルの出力品質、プロンプトの管理、および評価の設計に焦点を当てる **AI 開発者 / エンジニア** の役割を担います。

これは AI 開発者の品質保証レイヤーであり、開発中にエージェントの出力を手動で評価する*インナーループ*です。モジュール 6 では、これを自動化し、継続的にリグレッション（退行・デグレ）を検出する*アウターループ*にします。

== 学習目標

このモジュールを修了すると、以下のことができるようになります：

* Red Hat OpenShift AI で Jupyter ワークベンチを起動できる
* MLflow のプロンプトレジストリ (Prompt Registry) にバージョン管理されたプロンプトを登録できる
* 入力と期待される出力を含む評価データセットを作成できる
* ライブエージェントに対して決定的評価および LLM-as-a-Judge 評価を実行できる
* MLflow で評価結果とトレースごとのアセスメント（評価）を分析できる

== AgentOps において評価が重要な理由

Fed Aura Capital の住宅ローンシステムにおいて、エージェントは重大な決定を下します：

* プロスペクトエージェントは見込み客を審査します。偽陰性（誤って不適格と判断すること）は、30万ドルの住宅ローン販売の機会を失うことになります。
* アンダーライターエージェントはリスクを評価します。50万ドルの不良債権の承認は、規制上のリスクを生み出します。
* アンダーライターエージェントはコンプライアンスをチェックします。違反は、法的罰則やライセンス停止のリスクをもたらします。

本番環境では、わずか 1% のエラー率でも、1日 10,000 回のインタラクションにおいて毎日 100 回の失敗を意味します。メトリクスはエージェントが応答したことを教えてくれます。トレースはどのように応答したかを教えてくれます。**評価は、それが正しく応答したかどうかを教えてくれます。**

== 演習 2: リポジトリのクローンと評価ノートブックを開く

これが実践における*インナーループ*です。AI 開発者またはエンジニアとして、Jupyter ノートブックを使用してプロンプトを実験し、エージェントの動作を微調整し、出力をインタラクティブに評価します。ノートブックは高速なフィードバックサイクルを提供します。コードがパイプラインや本番環境に到達する前に、プロンプトを変更し、評価を再実行し、結果を検査して反復します。

TIP: MLflow の評価フレームワークについてさらに詳しく知りたい場合は、このページ上部の **MLflow Docs** タブを開き、https://mlflow.org/docs/latest/genai/eval-monitor/[Evaluation & Monitoring^] セクションを探索してください。スコアラー、データセット、および評価主導型の開発ワークフローについて詳しく説明されています。

== 演習 3: MLflow のプロンプトレジストリにプロンプトを登録する

評価を実行する前に、MLflow の https://mlflow.org/docs/latest/genai/prompt-registry/[プロンプトレジストリ (Prompt Registry)^] に、エージェントのシステムプロンプト（エージェントの役割と動作を定義する指示）を登録しましょう。プロンプトレジストリは、プロンプトのバージョン管理を提供します。これはシステムプロンプト用の Git のようなものと考えてください。これにより、変更を追跡し、バージョンを比較し、評価トレースを、それを生成した正確なプロンプトにリンクさせることができます。バージョン管理がないと、品質が低下したときに、どのプロンプトの変更が原因かを特定したり、安全にロールバックしたりすることができません。

. **1. Register System Prompt in MLflow** の下にある 3 つのセルを実行します。ノートブックは public-assistant (パブリックアシスタント) のシステムプロンプト (`config/agents/public-assistant.yaml` と同じ内容) を読み取り、バージョン管理されたアーティファクトとして登録します：
+
image::eval4.png[Notebook cell registering the public-assistant system prompt in MLflow Prompt Registry,link=self,window=blank,width=500]

. **MLflow Console** タブに移動します。**mortgage-ai-eval** 実験に切り替えます：
+
image::nav-mortgageaieval-exp.png[]
+
左側のサイドバーで **Prompts** をクリックします。
+
image::nav-prompts.png[]
+
登録されたプロンプトが表示されます：
+
image::eval5.png[MLflow Prompts page showing public-assistant-system-prompt at Version 1,link=self,window=blank,width=700]

. **public-assistant-system-prompt** をクリックして、バージョンの詳細を検査します：
+
image::eval6.png[MLflow Prompt detail showing version 1 with metadata and prompt text preview,link=self,window=blank,width=700]
+
プロンプトの詳細には以下が表示されます：
+
--
* **Version (バージョン)**: バージョン番号と登録のタイムスタンプ
* **Metadata (メタデータ)**: エージェント名、ペルソナ、ソースファイル、タイプのタグ
* **Commit message (コミットメッセージ)**: 変更の説明 (Git コミットのようなもの)
* **Prompt text (プロンプトテキスト)**: システムプロンプトの完全なコンテンツ
--

NOTE: システムプロンプトを更新して新しいバージョンを登録すると、MLflow は履歴を保持します。これにより、プロンプトのバージョン間で評価結果を比較できます。これは、大規模なプロンプトエンジニアリングにとって非常に重要な機能です。
